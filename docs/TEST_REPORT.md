## 3. 中文编辑能力测试

### 3.1 测试集

`scripts/make_test_set.py` 合成 10 段（普通/快速/压抑/愤怒/哭腔/耳语/长句/停顿/噪声 SNR20dB/背景音乐），
每段 3 种替换（词/短语/整句）= 30 任务。清单：`data/test-set/manifest.json`。

### 3.2 关键发现：保持类指令过多会抑制编辑（重要）

首轮 30 任务使用 5 条保持指令（音色+情绪+语速韵律+停顿+不夸张），ASR 文字准确性仅 **4/30 = 13.3%**。
对照实验（01-normal，词替换 会议室→发布会，seed=42）：

| 指令 | ASR 结果 | 编辑生效 |
| --- | --- | --- |
| 纯编辑指令 | …三楼**发布会**开会… | ✓ |
| +「尽可能保持原音色。」 | …三楼**发布会**开会… | ✓ |
| + 5 条保持指令（首轮 STYLE） | …三楼**会议会**开会… | ✗ 退化 |
| 纯编辑指令，seed=7 | …三楼**发布会**开会… | ✓ |

**结论与产品对策**：默认风格指令精简为「保持音色+情绪」两条；UI 增加实测提示；
编辑未生效时建议精简指令 / 换种子 / 改用 Base。此发现已写入 README 与使用说明页。

准确率演进（Flash，同一测试集）：长保持指令 13.3% → 精简指令 50% → 精简指令 + 整句 TTS 模板 + 不朗读风格指令 + 时长估算 **86.7%**。

### 3.3 指令模板对照实验（整句替换的关键发现）

整句替换用中文内容编辑模板 `把'整句'改成'整句'` 时两模型均失败（Flash 0/10）。
改用官方零样本 TTS **英文模板** `Say the following with the same voice: '新台词'` 后：

| 模型 | 模板 | 01-normal 整句 ASR | 04-angry 整句 ASR |
| --- | --- | --- | --- |
| Flash | 中文内容编辑 | ✗ 原句不变 | — |
| Flash | 中文 TTS「用同样的音色说」 | ✗ 新旧混合 | — |
| Base | 中文内容编辑 | ✗ 混合乱码 | — |
| Base | 中文 TTS | ✗ 原句+尾巴 | — |
| **Flash** | **英文 TTS** | **✓ 完整新句** | — |
| **Base** | **英文 TTS** | **✓ 完整新句** | **✓ 完整新句** |

**产品落地**：全文替换模式自动采用英文 TTS 模板；局部替换保持内容编辑模板。

### 3.4 第二个 bug：风格指令被读出

全文模式若在 TTS 模板后附加中文风格指令（「尽可能保持原音色和原始情绪」），
模型会把指令**当作台词朗读**（ASR 可见「…请大家提前到场小姐可能保持原音色和原始情绪」）。
**修复**：全文模式不附加风格指令（模板已含音色保持）；UI 在该模式隐藏风格控件并提示。

### 3.5 最终套件（修复后，Flash vs Base，各 30 任务，seed=42，8-bit）

- 局部替换：`把‘X’改成‘Y’。尽可能保持原音色和原始情绪。`
- 整句替换：全文模式英文 TTS 模板，目标时长按文本长度估算（≥源时长）。

**结果（ASR 客观验证，含同音字归一）：**

| 模型 | 词替换 | 短语替换 | 整句替换 | 总计 | 平均耗时 | 平均 RTF | 峰值 RSS |
| --- | --- | --- | --- | --- | --- | --- | --- |
| **AuK-Flash** | **10/10** | 6/10 | **10/10** | **26/30 = 86.7%** | 10.5s | 1.44 | 7.6 GB |
| AuK Base (32步) | 8/10 | 6/10 | 9/10* | 23/30 = 76.7% | 14.0s | 2.04 | 7.6 GB |

\* Base 02-fast-sentence 实为 ASR 同音字噪声（磨蹭→摩蹭），人工复核应为正确，即整句 10/10。

失败用例分析（两模型共性）：
- 「明天上午十点→后天下午两点」：日期/时段词替换成功，时间词「十点」锚定强，3 例未改（01/09/10 短语）。
- 「再也没有→再也没有过」（03-slow 短语）：细微体貌变化，两模型均忽略。
- Base 特有：02-fast-word 将「车」删除而非替换为「高铁」；07-long-word「实验→试验」未生效；08-pause-phrase 未生效。
- 情绪旁证：04-angry 全部 ANGRY、05-sad 全部 SAD（含整句），02-fast 全部 ANGRY（急促），编辑后情绪特征保留。

**结论**：优化模板后 **Flash 为更优默认**（更快且本测试集更准）；Base 作为备选用于 Flash 失败用例。
官方"Base 编辑跟随更准"的结论针对内容编辑模板；在零样本 TTS 模板下本机观察相反，如实记录。

数据与评分表：`data/test-results-flash-final/`、`data/test-results-base-final/`（summary.json / asr_verification.json / SCORESHEET.md / 30 候选 wav）。
对照历史：`test-results-flash-longstyle`（长指令 13.3%）、`test-results-flash`（精简指令 50%）、`test-results-base`（Base 内容编辑模板 43.3%）。

### 3.6 能力边界（如实记录）

- 词级替换：两模型多数成功（Flash 9/10，其中「他→她」为同音字，ASR 不可验证）。
- 短语替换：存在部分生效（如「明天上午十点→后天下午两点」两模型均改为「后天下午十点」，时间词锚定强）。
- 整句替换：英文 TTS 模板下大幅改善；情绪保持弱于内容编辑模式（TTS 模板只保证音色），
  个别用例情绪漂移（05-sad 整句被 ASR 判为 HAPPY）。
- ASR 验证存在同音字噪声（磨蹭→摩蹭 等），文字准确性为保守下限。
- 官方文档同样声明 Base 比 Flash 编辑跟随更准，且 cookbook 存在模型本身失败例——与本机观察一致。
- **产品对策**：换种子多次生成挑选候选；短语/整句替换不做成功承诺；拼接导出保留未修改区域原声；
  情绪定制引导至自定义指令模式。

### 3.7 情绪保持（ASR 情绪检测，客观旁证）

SenseVoiceSmall 对生成音频的情绪识别：04-angry→ANGRY、05-sad→SAD、02-fast→ANGRY（急促）、
其余 NEUTRAL。愤怒/悲伤特征在编辑后保留。主观情绪一致性仍需用户试听评分。

## 8. 结论

- 部署、Web 功能（UI 自动化 12/12）、数据保护、运维脚本全部验收通过。
- 8-bit 为默认精度（与 fp32 相关 0.9976，sequential bit-identical）。
- 中文编辑最终准确率：Flash **86.7%**（词 10/10、整句 10/10、短语 6/10）；Base 76.7%。
- 三项实测驱动的产品修正（精简保持指令 / 整句 TTS 模板 / 不朗读风格指令）使准确率从 13.3% 提升至 86.7%。
- 短语替换存在模型能力边界（时间词锚定等），已如实记录并提供对策（换种子 / 多候选 / Base 备选）。
